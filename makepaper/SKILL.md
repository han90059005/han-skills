# makepaper

把一组 Markdown 资料读入后，按用户每次给出的要求合成或修改一篇高质量中文论文：正文用 `[n]` 角标交叉引用，文末附「参考文献」表。输出为 Markdown，可直接交给 makelatex 编译成 PDF。

## 与其他技能的区别

本技能只负责「依据文献 md 合成或修改论文/综述正文 + 参考文献」；复习笔记生成/合并用 course-review-generator，交互式笔记维护用 makenote，最终排版转 PDF 用 makelatex、转 Word 用 makedocx。

## 输入接口（归一化）

源 md 可能来自 paper-finder、Zotero 插件、mineru、course-review-generator 等，格式不统一。写作前先把每份源 md 归一化成一条「文献记录」，再做证据判断与写作。

对每份源 md：

1. **定标题**：取首个 `# 标题`；无标题则用文件名兜底。
2. **提元数据**：从 `**作者**：`、`- 作者：`、`作者：`、`年份：`、`期刊：`、`DOI:`、`**DOI**：` 等写法中提取作者/年份/期刊/DOI；若 paper-finder 写了 `**来源类型**`、`**证据级别**`，一并读入，作为后续判断依据。
3. **判深度**（优先级从高到低）：
   - 有 `## 全文` / `## 全文（自动提取）` 或很长的正文 → 全文级；
   - 有 `## 摘要` / `### 摘要` / `- 摘要：` / `Abstract` → 摘要级；
   - 只有标题与元数据 → 仅元数据，只登记来源。
4. **清洗**：剔除水印行、乱码、多余空行；统一用空行分段。
5. **编号**：给每条记录稳定编号 `[n]`，全文保持一致，供正文引用。

归一化完成后进入证据判断与写作；输出仍是 Markdown。

## 证据分级（内部工作约束）

分级衡量的是**当前手里的材料能支持到什么程度**，与期刊档次、作者权威或摘要里的措辞强度无关；A/B/C/D 也不是论文质量排名。

归一化每篇源 md 时，顺带记两项：**来源类型**（原始研究 / 综述 / 预印本 / 机构或新闻稿 / 二手转述；网页抓取转存的 md 也要这样标）和**可核范围**（全文 / 仅摘要 / 仅元数据；paper-finder 生成的 md 里写作 `**证据级别**`）。写正文前，对核心主张建一张内部对照表（默认不输出，用户要时才给）：

| 关键主张 | 来源与原文要点 | 类型 | 独立研究数 | 局限 / 待核 |
|---|---|---|---|---|

- **A｜直接观察或结果**：来源明确报告了实验现象、测量值或比较结果。只代表"来源这样报告"，不代表已独立验证，也不代表全文的对照、统计与实验条件都已核实。
- **B｜作者解释或机制**：来源把结果归因于某机制，但当前材料无法确认全文是否有直接证据。
- **C｜综合推断**：由多条信息合并得出，不能挂 `[n]` 冒充某篇论文的实验结果或作者原话；确需引用时写成"综合……[n]"，并让读者看出这是本文归纳。
- **D｜无法核实**：摘要缺关键条件、数值来源不明、引用关系不清或机制无法确认。不写进结论；必要时用一句话披露局限。

约束：

- 摘要级来源只能支撑"摘要报告了……"，不写"研究证实/全文表明"，不补造实验细节、样本量、对照或统计显著性。
- 写"作者未在摘要中提供该证据"，不写"作者没有提供证据"——后者要核查全文才能成立。
- 证据不足时降低结论强度、缩小主张范围或标注待验证；不要用模型常识填补缺失证据。
- 证据不足不等于拒绝回答：能确认的部分照常写，只限定不能确认的部分。
- A/B/C/D 只作内部约束，正文不逐句贴标签。

## 多来源不等于多证据

计数前先判断来源是否独立：

- DOI 相同，或标题+作者+年份相同 → 同一研究；
- 同一论文的网页版、PDF 版、机构库版或不同转载页面 → 同一研究；
- 预印本与正式发表版 → 同一研究，优先引正式版；
- 综述转述原始研究 → 综述算二手，原始数据回引原研究；拿不到原文时写"据……综述"；
- 新闻稿、机构网页、百科/公众号等 → 二手，不计独立证据；
- 不同论文的材料组成、实验条件、指标定义或应用场景不一致 → 不能合并成"多项研究一致支持"。

核心论点优先追溯原始研究。来源冲突时保留冲突并说明条件差异，不要挑措辞最强的一条。只有来源独立性、关键数据或核心论证确有疑问时才定向补检，不做全量复核。

## 因果审查（重点）

对每条核心主张，按五层拆开：

1. **观察**：实际测量或报告了什么？
2. **关联**：哪些变量或现象同时变化？
3. **解释**：作者认为这种变化由什么引起？
4. **机制**：中间环节是否有证据支持？
5. **因果结论**：能否排除主要替代解释？

逐条检查：

- 结果变量和被解释变量是否明确？
- 所提出的原因是"有证据"，还是只与结果同时出现？
- 声称的机制链，各关键环节是否都有支持？
- 有无未控制变量、实验条件差异、反向因果或其它合理解释？
- 是否把作者的机制假说写成已被直接证明的事实？
- 是否把性能变化直接归因于某个结构特征，忽略配方、工艺、测试条件等其它因素？
- 是否把单一体系的结果泛化到所有同类材料？
- 结论是否超出实验条件、样本范围或摘要实际报告的结果？

### 措辞对照

| 证据状态 | 写法 |
|---|---|
| 有明确观察，因果未验证 | "观察到""与……相关""伴随……变化" |
| 作者解释，尚无法核实 | "作者将其归因于……""该结果可能与……有关" |
| 多项证据支持机制，仍有不确定性 | "支持……机制""表明……可能参与" |
| 直接、充分且一致的因果证据 | "导致""促进""通过……实现"（限定在证据覆盖范围） |

不要机械地把强结论改成"可能"；原研究有充分因果证据时保留强度。也不要因为作者用了 demonstrate / reveal / prove / enable / first / unprecedented 就自动采信；摘要里的 revolutionary / breakthrough / unprecedented 是作者评价，不是结果，改写时换成可核数据与条件。

相关性研究、现象报告和探索性研究同样可以引用，关键是准确说明它们实际回答了什么，而不是强行升格为因果结论。

## 主张与引用可追溯

核心主张必须能沿"正文 → `[n]` → 源 md 的原句/段落"走通。交付前逐条核对：

- 数值、单位、温度、时间、比例必须能在源 md 中逐字找到；相近材料/体系（如 Ag₂Se 与 Ag₂S）尤其要逐项对表，不凭记忆改写，不擅自换算或四舍五入；
- 引用存在，但不支持对应的具体主张；
- 引用只支持一般背景，却被用来支持特定机制；
- A 材料的结果被安到 B 材料上（如 Ag₂Se 与 Ag₂S 的数据混淆）；
- 理论计算写成实验事实；
- 作者推测写成已证实机制；
- 不同测试条件下的数值直接比较；
- 二手来源当作独立的原始证据。

保持原有引用格式、编号和 LaTeX 命令；确需调整引用时，确保新来源确实支持该主张。不伪造 DOI、标题、作者、数据，也不为凑数量加无关文献。

## 阅读检索输入口（按标签筛选）

若文献目录下存在 makelibrary 生成的 `_index.json`，先按标签检索、再读文件，避免反复读全文：

1. 读 `_index.json`，把标签及篇数列给用户，确认本次要用哪些标签。
2. 按选定标签筛出文件路径。
3. 只读命中的文件进入归一化与构建；未命中的不读。

若目录没有索引，可先运行 makelibrary 建索引；没有索引时退回「读全部 md」的旧流程。

## 强度机制

- **低强度（默认，量产小论文）**：模板一次成文，引用点到摘要/全文表层；主张表只列 3–5 条主干，一次结构化检查，不额外检索。适合课程小论文、综述速成。
- **高强度（精写）**：
  1. 先按用户思路出提纲，每一段的主题与侧重点由用户定，确认后才动笔；
  2. 逐段展开，引用落到段落级、具体到论据与数据；
  3. 校验重——建完整主张对照表，逐段查引用是否准确、因果是否越级、独立来源是否足够、结论是否有据、字数是否达标；仅在关键主张存疑时定向补检。

触发：请求中说明「精写 / 详细 / 正式」→ 高强度；未说明 → 低强度；拿不准时先问一句强度。

## 每次必须确认的三项（缺一先向用户补齐，不要硬猜）

1. **源地址**：要阅读的源 `.md` 所在目录（修改任务则是原文章 + 相关文献目录）
2. **生成地址**：论文 Markdown 写到哪个目录、文件名
3. **具体要求**：内容主题、结构、字数；修改任务还要确认「要改什么、哪些不能动」

## 工作流

### A. 新写论文

1. 若存在 `_index.json`，先按标签筛选（见「阅读检索输入口」），只读命中的 `.md`；否则列出并读完源文件夹内所有 `.md`（忽略非 md 文件）。源 md 只读、不修改。
2. 逐个判断内容类型与来源类型，决定能引用到什么深度：
   - 有 `## 全文`（或很长的正文）→ 全文可用，可深入引用；自动提取的全文仍要防 OCR/版式错误；
   - 只有 `## 摘要` → 只能引摘要级信息；
   - 只有元数据（标题 / 作者 / 年份 / 期刊 / DOI）→ 仅登记为来源，正文尽量不直接依赖。
3. 给每篇源 md 分配稳定编号 `[n]`，建立「源文件 → 编号」一一映射。
4. 先提核心论点（通常 3–8 条；低强度可只列 3–5 条主干），填内部「主张—证据」对照表，标出 A/B/C/D，检查独立来源数与因果链。证据不足先调整论点强度，不要先写强结论再找文献背书。
5. 按证据组织段落：观察 → 关联 → 解释 → 机制 → 结论，逐层递进，不跳层。
6. 按用户要求撰写正文：
   - 严格满足内容主题、结构和字数要求；
   - 引用某篇来源时，在该句末写 `[n]`（多个用 `[1,2]`，连续用 `[1-3]`）；
   - 内容必须来自源 md，不臆造数据、结论或文献；源 md 没有的信息要克制，必要时明确说明「未覆盖」。
7. 文末写 `## 参考文献`，每条以 `[n]` 开头，信息取自对应源 md（作者、标题、期刊、年份、DOI）。
8. 写到用户指定的生成地址（文件名默认用题目 slug，或按用户指定）。
9. 交付前做一次结构化核对：引用是否对应、因果措辞是否越级、独立来源计数是否正确、数值/单位/条件是否逐个对回源句。不必逐句重读。

### B. 修改已有文章

1. **先盘点（此阶段不改写）**：列出核心主张及对应 `[n]`，标出疑似事实错误、引用不匹配、因果跳跃、过度概括、材料/条件混淆。
2. **先修论证，再润色语言**：保留作者原有有效内容、术语、数据、引用编号和文章结构。
3. 不为「显得更有说服力」而强化因果；不在无依据时新增机制、性能优势或文献结论。
4. 必须改变核心主张时，说明理由（回复里给简短清单），不要静默改写。
5. 输出改后全文 + 3–6 条「实质性改动」说明；纯文字润色不必逐条列。

## 成本控制

- 复用已读入的源 md 和已建好的对照表；不逐句检索。
- 普通背景轻检查；核心机制、关键性能比较、决定结论的主张才严格核对。
- 默认不查全文；仅当核心主张无法用摘要判断、且全文可得时，才定向读相关段落。
- 一次结构化检查覆盖多条主张；证据不足就标 D 并停止推断，不无限补检。
- 低强度不建完整对照表、不做额外检索；高强度才逐段核对并定向补检。

## 输出格式（与 makelatex 兼容）

- 第一个 `# 标题` 作为论文标题；
- 如需署名，标题后放「姓名 / 学号 / 作者」「日期」行；
- 正文空行分段，`[n]` 直接写在正文里；
- 最后 `## 参考文献` + 以 `[n]` 开头的条目。

若用户要求「转成 PDF」，再调用 makelatex 技能把这份 Markdown 编译为 PDF。
