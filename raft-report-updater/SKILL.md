# Raft Report Updater（通用版）

一个项目无关的实验报告自动更新工具。读取项目目录下 Excel 数据源和现有 Markdown 报告，对比新旧数据差异，检测矛盾冲突，生成/更新完整实验报告。

## 适用场景

任何以 **Entry 编号** 组织实验数据的项目，例如：
- 聚合物可控聚合（RAFT/ATRP/NMP）条件筛选
- 有机合成反应条件优化
- 材料性能测试矩阵
- 催化剂活性评价实验
- 任何 "条件变量 → 结果" 形式的数据表

## 项目配置

在项目目录下放置 
eport_config.yaml，工具自动识别并使用。若无配置文件，工具进入**自动检测模式**（扫描目录下所有 .xlsx 和 .md 文件，尽力推断）。

### 配置示例（完整）

+"``yaml"+@"
project:
  name: "RAFT可控聚合"              # 项目名称，用于报告标题
  report_pattern: "RAFT可控聚合（*"  # 搜索已有报告的 glob 模式
  report_name: "RAFT可控聚合（{date}）.md"  # 新报告文件名模板

excel_sources:
  - file: "数据汇总.xlsx"            # Excel 文件名（相对项目目录）
    sheet: "全部数据"                # Sheet 名称（可选，默认第一个非空 sheet）
    header_row: 1                    # 表头所在行号（可选，默认自动检测）
    data_start: 2                    # 数据起始行（可选，默认表头下一行）

columns:                             # 列定义
  - name: Entry                      # 列名（必填，必须包含 Entry）
    label: "Entry"                   # 报告中表头显示（可选，默认同 name）
    type: int                        # 列类型: int/float/str（可选）
  - name: Monomer
    label: "单体"
    type: str

categories:                          # 实验分组，用于生成分析表格
  "Lag种类":                         # 分组名称 → 作为分析章节标题
    entries: [54, 55, 56, 57, 77]   # 该组包含的 Entry 编号
    title: "Lag 种类比较"            # 表格上方标题（可选）
    condition: "30 Hz, 60 min"       # 条件描述（可选）
    hide_cols: ["Monomer"]           # 隐藏的列（可选）

  "另一组":
    entries: [1, 2, 3, 4]

# 如果不配置 categories，工具会尝试按列值自动分组
"+"``"+@"

### 最简配置

只要目录下有 .xlsx 和 .md 文件，工具就能工作。最简配置只写必要信息：

+"``yaml"+@"
project:
  name: "我的实验项目"
"+"``"+@"

## 工作流程

### 1. 扫描项目目录

工具首先查找 
eport_config.yaml，读取配置；若无配置则自动检测：
- 所有 .xlsx 文件 → 按修改时间排序，取最新者为主数据源
- 所有 .md 文件 → 按文件名中的日期排序，取最新者为旧报告
- 自动推断列名（从 Excel 表头行）
- 自动分组（按 Lag、Abrasive、Monomer 等列的不同值）

### 2. 读取 Excel 数据

- 支持 .xlsx（仅 openpyxl 兼容格式）
- 按 sheet 名称或自动选择有数据的 sheet
- 自动识别表头行（寻找含 "Entry" 的列）
- 跳过空行、汇总行、无效数据行

### 3. 读取现有报告

- 解析 Markdown 报告中的数据表格
- 按 Entry 编号匹配，识别新增/变更

### 4. 对比差异 & 检测矛盾

这是工具的核心功能。对每条 Entry，逐列对比新旧值：

- **新增 Entry**：旧报告中不存在
- **数值变更**：同一 Entry 的数值列发生变化
- **矛盾检测**：新旧结论冲突时列出所有冲突点

### 5. 生成/更新报告

- 合并 Excel 数据和旧报告的分析文案
- 按 categories 配置生成分组分析表格
- 附录列出全部数据
- 更新日志自动追加更新记录
- 按 {date} 命名新报告文件
- 保留旧报告不删除（仅重命名归档）

## 报告结构

自动生成的报告包含以下章节（由数据驱动，不同项目可能不同）：

+"``"+@"
# {项目名称} 实验报告

## 一、体系概览
  （来自配置或自动检测的组分、反应式、评价指标）

## 二、结果与分析
  ### 2.1 {分类1名称}
  ### 2.2 {分类2名称}
  ...
  （根据 categories 配置自动生成）

## 三、综合结论
  （初次生成时留空，标记为"待人工补充"）

## 四、附录：全部数据
  （完整数据表，按 Entry 排序）

## 更新日志
  （自动维护，记录每次更新日期和变更摘要）
"+"``"+@"

## 触发规则

- **触发词**：「更新报告」「刷新报告」「加数据」「添加实验」「update report」
- **场景识别**：用户提到 Excel 数据变更、新增实验、报告过期时触发
- **不确定时先确认**：如果不确定是否应该触发，先向用户确认项目目录和数据源
- **新项目首次使用**：需要先确认项目目录，帮助创建最小配置文件

## 数据矛盾处理规则（最高优先级）

当新数据与旧结论出现矛盾时，遵循：

1. **不留余力地分析矛盾**：逐条对比新旧数据，找出所有冲突点
2. **不掩盖冲突**：矛盾本身就是重要的实验信息
3. **保持最终文字的逻辑性**：先陈述矛盾，再给解释（误差/条件变化/新发现）
4. **标注不确定性**：无法解决的矛盾标注"待验证"或"需重复实验"
5. **保留历史脉络**：在更新日志中记录被修改的结论及原因

## 关键行为

- 新数据点 → 追加到附录数据表末尾
- 已有数据点更新 → 覆盖对应行
- 分析章节 → 根据新数据重新计算表格，但保留人工撰写的分析文案
- 文件名 → 使用当天日期
- 旧版本 → 保留不删除（重命名归档：OLD-{原文件名}），用户可能回退

---

*此工具的设计哲学：数据与文字分离。数据来自 Excel（机器可读），分析来自人工（保留覆盖风险），工具负责两者的精确对齐和矛盾发现。*
